01 / What this project does

MediFind AI is a Python application built with Streamlit. It has three tabs: Prescription review, Medicine reference, and Report review. A separate optional Google Shopping demo displays unverified search listings after a user confirms synthetic medicine details.

Important: This is a learning prototype. It is not clinically validated, does not diagnose or prescribe, and must not be used for patient care or purchase decisions. AI can invent or misread information. A source link or a user confirmation does not make an output medically verified.

The prototype has no authorized pharmacy feed and does not establish that a listing matches a prescription or has an equivalent pack size. The small sample catalog is not used to approve or reject a medicine.

02 / Get it running

  1. Install Python 3.11 or newer, uv, and the Tesseract program. On macOS with Homebrew: brew install tesseract.
  2. In the project directory, run uv sync. This creates a virtual environment and installs the versions recorded in uv.lock. The first install and first embedding-model download can take time and need network access.
  3. Add GOOGLE_API_KEY to the local .env file for Gemini. Add SERPAPI_API_KEY only for the optional shopping demo. Use your own credentials and do not share or commit them.
  4. Start the app and open the local address printed in the terminal:
uv run streamlit run app.py

Run the tests from the project root with uv run python -m unittest discover -s tests -v. The tests use mocks for external services; passing tests does not establish clinical accuracy or verify a live API connection.

The default server address is 127.0.0.1. Local binding is not authentication and does not protect an app exposed through a tunnel or proxy. See the README before considering any hosted deployment.

03 / How the parts fit

Streamlit UIService functionsLocal data or external APIsReviewed output

app.py owns the UI, validates uploads, controls session state, and calls the service modules. A service is a Python module grouping related work: image extraction, shopping search, report comparison, or reference retrieval. The data directory holds examples and a generated vector index. The tests directory checks individual functions and UI behavior.

Streamlit and session state

Streamlit reruns the script when a user interacts with a widget. st.session_state stores things such as the current image identifier, editable rows, confirmed rows, and shopping results between reruns. This avoids repeating a provider request for every button press. A changed or removed upload clears the related review state. Clear session clears local session state; it cannot erase data already sent elsewhere.

What is a DataFrame?

A pandas DataFrame is a table with named columns. Here it stores editable medicine rows (form, name, strength) and report rows (name, result, unit, reference_range). Confirmation saves a copy; changing the table means the displayed copy no longer matches and the user must confirm again.

04 / Prescription review

UploadValidateOCR + GeminiReviewConfirm
  1. Disclosure and upload: The UI warns that uploading sends the entire image to Google Gemini. Only PNG or JPEG files up to 10 MB and 20 million pixels are accepted. Use synthetic samples for development.
  2. Local OCR: Tesseract converts image pixels into possible text. extract_medicines uses a regular expression, a text-matching pattern, to find a limited form/name/mg-strength structure. It is not a general prescription parser.
  3. Vision extraction: The image is converted to PNG and encoded as base64, a text representation of binary data. extract_prescription_candidates sends it to Gemini with instructions not to guess. The response is parsed as JSON and checked for exactly three string fields.
  4. Combine and review: combine_candidates keeps conflicting or incomplete readings separate and removes exact complete duplicates. A person can edit the table and must verify each field against the image. Some names receive a short, source-linked general reference, not a prescription match.
  5. Confirm: A nonempty name, strength, and form are required for every row. Confirmation is a user action, not clinical verification. The shopping demo appears only while the confirmed table still matches the edited table.

If local OCR fails, Gemini is still attempted. If Gemini fails, available OCR results remain for review. Neither path guarantees correct or complete extraction.

05 / Optional shopping demo

Confirm synthetic detailsChoose medicineClick searchReview unverified listings

The selected name, strength, and form become a search query sent to SerpApi only after an explicit click. The provider may retain the query and results. Do not send real patient information. search_shopping requests India-oriented Google Shopping results, checks the response shape, and retains rows with a title, seller/source, and displayed price.

Links are accepted only for the expected HTTPS Google search URL shape; they are Google result links, not guaranteed direct retailer links. The UTC timestamp is when this app fetched the results, not when a seller updated them. Availability, source identity, medicine equivalence, and prices are not verified.

Sorting and pages

sort_listings leaves relevance in provider order. For price order it uses Decimal only when a single displayed INR amount agrees with the provider's numeric amount; ambiguous prices are placed last. The UI shows four items per page and reuses the saved results when sorting or paging. Sorting is not a price comparison of equivalent packs.

06 / Report review

Upload imageGemini transcriptionCorrect fieldsCompare printed range

Report images have the same size, format, and privacy restrictions as prescription images. Gemini is asked to transcribe test name, result, unit, and the range printed for that result. The response is validated as a JSON list of objects with exactly those four string fields. If extraction fails, the user can enter values manually.

After the user checks the fields and selects Compare checked results, compare_printed_range uses decimal arithmetic for a single number and a two-sided numeric range. For example, a checked result of 8 with range 5-10 is labeled OK (within range). A name and unit must be present. The code does not verify that the entered unit matches the printed range: a person must check that.

Missing or ambiguous values, inequalities, qualitative results, and invalid ranges return Not compared. Low and high are displayed in amber, in-range in green, and not compared in gray. These labels and colors do not indicate urgency, diagnose a condition, or interpret narrative findings.

07 / Medicine reference and RAG

Retrieval-augmented generation (RAG) gives a language model selected reference text along with a question. The goal is to ground its answer in that text, although retrieval and prompt instructions do not guarantee correctness.

DocumentsChunksEmbeddingsChroma searchFiltered contextGemini answer or abstention
  1. Documents: A LangChain Document combines text with metadata such as its source and verification status. The app includes a small set of source-checked NHS summaries in VERIFIED_REFERENCES; these have not been independently reviewed by a clinician.
  2. Chunking: chunk_documents splits the illustrative text files into pieces of up to 300 characters with 50 characters of overlap. Overlap helps preserve context across a split.
  3. Embeddings: all-MiniLM-L6-v2 converts text into numerical vectors that can be compared for semantic similarity. The model may need to download on first use.
  4. Vector store: Chroma stores the vectors in data/vector_store. The app loads or builds the store and adds the source-checked summaries by stable ID if missing. The example text files lack verified metadata and are excluded from the answer retrieval filter.
  5. Retrieval: Only a narrow set of general question patterns about supported medicine names is accepted. Search filters by verified status and the requested medicine's source; results beyond the configured distance threshold are discarded. A similarity score is not proof of truth or medical safety.
  6. Generation or abstention: A prompt asks Gemini to answer only from retrieved text, avoid treatment advice, and abstain if context is insufficient. Unsupported questions or missing context receive an abstention. If generation fails, the service can return a busy message and a source-linked excerpt that may not answer the question.

In the prescription tab, an exact known name can also display its short general summary directly; that display is separate from the question-answer retrieval flow.

09 / Test and troubleshoot

uv run python -m unittest discover -s tests -v
uv run python -m unittest discover -s tests -p 'test_report_service.py' -v
uv run python -m unittest discover -s tests -p 'test_vision_ui.py' -v

The first command runs all tests; the others run one test file at a time. unittest.mock replaces external calls with controlled responses, making tests repeatable without sending real data. When changing a service, start with its tests, then run the full suite.

  • Local OCR fails: Check that the Tesseract program is installed and available on the terminal PATH, not just the Python wrapper.
  • Gemini fails: Check the local key, provider access, network, model availability, and provider limits without printing the key. An extraction failure does not prove that the prescription is blank.
  • Shopping is unavailable: Check that the optional SerpApi key is configured and that the provider is available. Search requires confirmed synthetic rows and an explicit click.
  • Reference setup is slow or fails: The embedding model may need a first download; Chroma needs permission to write its local index. A successful retrieval is not clinical validation.
  • Unexpected old session data: Use Clear session or remove the uploaded image. This only clears the app session and does not erase provider copies.

10 / Safety and data boundaries

  • Uploading automatically sends the whole image to Google Gemini after the visible disclosure; it can include identifying information. De-identification alone does not guarantee anonymity. Gemini free-tier terms may permit use of content to improve products.
  • Shopping sends the selected query to SerpApi, which may retain it. Use synthetic demo data only. Do not treat results, prices, or links as verified pharmacy offers.
  • Local mode has no login. Experimental OIDC checks are not a complete production security design. Never expose the local app through a tunnel or proxy without an independently reviewed deployment.
  • Keep keys, images, user reports, sensitive logs, and evaluation data out of Git. Session clearing cannot delete data already sent to a provider.
  • Never infer illegible names, automatically substitute medicines, diagnose, recommend treatment changes, or treat a reported condition as a verified diagnosis. Seek qualified clinical review for uncertain information.

See Before patient use in the README for the outstanding clinical, privacy, security, and pharmacy-integration work.

11 / A small learning path

  1. Run the app with a synthetic image and locate the matching UI code in app.py. Observe how editing a row affects confirmation.
  2. Read compare_printed_range and run its test file. Add one example on paper, predicting whether it should compare before checking the result.
  3. Trace a general reference question through answer_question, the metadata filter, and the prompt. Identify where unsupported questions are rejected.
  4. Read a mocked shopping test and follow the query from button click to search_shopping. Consider why sorting cannot establish product equivalence.
  5. Before adding a feature, define its safety boundary and one focused test. Keep changes small and discuss the next milestone before building it.
